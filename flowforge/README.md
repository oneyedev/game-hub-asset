# Flowforge — 아트 디자이너 제작·납품 가이드

이 문서는 **게임에서 실제 교체 가능한 PNG 제작**을 위한 작업 안내다. 공통 저장소 규칙은 [상위 가이드](../README.md)를 따른다. 디자인 세트 목록의 유일한 운영 원본은 [`sets.json`](sets.json)이다. 게임 코드에 남은 세트 목록은 원격 로딩 실패 시 폴백이다.\n\n게임 소스 기준은 [games-hub](https://github.com/oneyedev/games-hub)의 `game/dev_asset_proxy.gd` 및 해당 타워의 실제 렌더링/아트 코드다. 이 문서는 게임 코드에 존재하지 않는 애니메이션 규격을 임의로 확정하지 않는다.

## 현재 구현과 향후 제작 규격의 구분

| 항목 | 현재 런타임 지원 | 디자이너 작업 지침 |
| --- | --- | --- |
| 전체 세트 A/B | 지원 | 세트별 일관된 색감·실루엣·재질을 유지 |
| 세부 후보 상속 | 지원 | 바뀌는 파일만 별도 오버라이드 |
| 기본 아처 후면 `tower_back.png` | 매핑됨 | 원본과 동일한 크기·여백·기준점 |
| 다른 타워 레이어·몬스터·배경 | **현재 Art Studio 매핑 미등록** | 제작 전 코드 매핑과 파일 규격 확정 필요 |
| Sprite2D/TextureRect | 원본 `res://` 경로가 있으면 자동 교체 | 원본 경로 보존 |
| `_draw()` | `resolve_texture()` 호출 위치만 교체 | 담당 개발자가 호출 연결 |
| AnimatedSprite2D/셰이더 | 자동 교체 **미지원** | 이미지 납품만으로 적용된다고 간주하지 않음 |

## 아트 디렉션
- 카메라: 위에서 비스듬히 내려다보는 판타지 타워 디펜스 시점. 원근·지면 접촉·그림자 방향을 세트 내에서 통일한다.
- 스타일: 작은 화면에서도 실루엣이 읽히는 킹덤러시 계열의 판타지 TD 감각을 참고하되, 타 작품의 원본 그림을 복제하지 않는다.
- 통일 기준: 외곽선 두께, 채도, 명암 단계, 목재·석재·금속 질감, 지면 기준선, 캐릭터와 건물의 상대 크기.
- 가림: 후면 건물 → 캐릭터 → 전면 울타리·난간 순서로 보이는 구조를 고려한다. 실제 씬의 Y 정렬·레이어 순서는 코드 확인이 필요하다.
- 원본과 같은 캔버스 안에 각 파트를 정렬한다. 파일마다 임의로 타워를 크게 만들거나 아래로 옮기지 않는다.

## 폴더 및 이름 규칙
```text
flowforge/
  README.md
  sets/
    forest/
      towers/
        archer/base-i/tower_back.png
      monsters/
      environment/
    stone/
      towers/
        archer/base-i/tower_back.png
      monsters/
      environment/
```
새 디자인 세트 추가 시 `flowforge/sets.json`의 `sets` 배열에 `id`, `label`, `root`를 추가한다. 게임 재배포 없이 Art Studio의 Reload로 목록을 다시 읽는다. 부모가 있는 세부 후보는 `parent`를 지정하고 부모 항목 뒤에 배치한다. 위 `sets/` 경로는 **확장할 때 사용할 규약**이다. 지금은 아래 기존 파일을 **`sets.json`의 `overrides`**로 연결해 사용한다.

| 세트 | 현재 실제 참조 파일 | 게임 내 원본 |
| --- | --- | --- |
| Forest(A) | `flowforge/archer/base-i/variant-a/tower_back.png` | `res://game/art/archer/base_i_two_unit/tower_back.png` |
| Stone(B) | `flowforge/archer/base-i/variant-b/tower_back.png` | 동일 |
| Forest → 아처 세부 후보 | 위 Stone(B) 파일을 아처에만 덮어씀 | 동일 |

현재 A/B 파일은 **기능 확인용 도형**이지 완성된 타워 디자인이 아니다. `flowforge/sets.json`은 세트 발견용 목록이며, 새 이미지 리소스 매핑은 게임 코드의 `ART_SET_ASSETS`에 여전히 필요하다. 신규 파일을 `sets/forest/...`에 올리더라도 `sets.json`의 기존 `overrides`가 우선하면 화면에는 기존 파일이 나타난다. 경로 변경 시 게임 코드 담당자에게 매핑 수정이 필요하다.

## 타워 제작 템플릿: 원본을 기준으로 납품

**작업 의뢰서(타워마다 채워서 사용)**

| 필드 | 입력할 내용 |
| --- | --- |
| 타워 ID / 레벨 / 특화 | 예: `archer/base-i` |
| 기준 세트 | `forest` 또는 `stone` |
| 게임 원본 리소스 | 정확한 `res://...` 경로 |
| 출력 상대 경로 | `sets/<set-id>/towers/<tower-id>/<file>.png` |
| 출력 캔버스(px) | **원본 파일을 열어 측정** |
| 레이어별 파일 | **현재 타워의 렌더링 코드를 확인해 확정** |
| 프레임 배열·방향 | **실제 애니메이션 리소스를 확인해 확정** |
| 기준점·바닥선·투명 여백 | 원본 이미지와 일치 |
| 동작 검증 | Original ↔ 세트 전환, 공격/대기/방향 전환, 가림 확인 |

### 레이어 설계와 파일별 역할
일반적인 타워 제작 시 검토할 레이어는 다음과 같다. **아래 이름은 역할 설명이며 모두 실제 파일로 존재한다는 뜻이 아니다.**

1. **건물 후면:** 기단, 지붕 뒤, 뒷벽, 구조물. 현재 아처에 매핑된 실제 파일명은 `tower_back.png`.
2. **캐릭터:** 궁수·마법사·조작 인원. 대기/공격/방향별 이미지와 스프라이트 시트는 **타워별 코드 확인 후 파일명·프레임 수를 결정**.
3. **건물 전면:** 난간·울타리·전경 장식. 캐릭터가 자연스럽게 가려지도록 별도 레이어 고려.
4. **효과·발사체:** 화살, 총탄, 마법, 연기 등. 캐릭터 프레임에 임의 합성하지 않고 렌더링 방식을 확인.
5. **바닥·그림자:** 게임 공통 지면과 충돌하지 않게 기준점·투명도를 확인.

### 타워 계열별 아트 요구
- **아처·엘프·드워프:** 타워와 캐릭터를 구분하고, 활·총의 조준 방향과 공격 포즈를 일치시킨다. 기본 아처의 2인 배치와 드워프 저격수/개틀링 등의 인원 차이를 작업 의뢰서에 명시한다.
- **마법사:** 기본적으로 캐릭터 1명. 마법 속성별 색채를 구분하고 시전 동작을 표현한다.
- **공성:** 인물보다 기계가 주인공. 조작 인원은 타워에 따라 0~3명이며 임의로 통일하지 않는다.
- **공병·배럭형:** 장치·설치물·소환 병력은 타워 본체와 별도 에셋이 필요할 수 있다. 실제 게임 리소스 경로를 확인한 뒤 납품한다.

**주의:** 위는 아트 기획 제약이다. 현재 Art Studio가 모든 타워의 캐릭터·프레임을 자동 교체한다는 의미가 아니다.

## 디자이너 납품 순서
1. 담당 개발자에게 **원본 PNG와 렌더링 경로, 필요 파일 목록**을 받는다. 미등록 범주는 매핑부터 요청한다.
2. 동일 세트의 스타일을 기준으로 원본 캔버스·레이어·프레임 규격을 유지해 제작한다.
3. 지정된 경로에 정상 PNG를 업로드한다. 프레임 배열/방향을 임의로 변경하지 않는다.
4. [Flowforge 게임](https://games.oneyedsoft.click/td-pilot/index.html)을 열어 우측 하단 **Art Studio**에서 세트를 전환하고 Reload한다.
5. 원본 폴백인지 실제 교체인지 확인하고, 크기·가림·대기/공격·다른 화면 크기를 검수한다.
6. 후보가 채택되면 세트 스타일을 유지해 다른 타워로 확장한다. 개별 수정은 기준 세트 상속 + 파일별 오버라이드로 관리한다.

## 문제 해결
- **이미지가 안 바뀜:** 코드의 `sets.json` 세트 등록 및 `ART_SET_ASSETS` 매핑 여부 → `overrides` 우선순위 → 경로 대소문자 → Raw URL 순서로 확인.
- **PNG load failed / Decode failed:** HTTP/CORS 또는 이미지 자체의 IDAT/디코딩 문제. 정상 PNG로 다시 내보낸다.
- **일부 레이어만 바뀜:** 현재 아처 후면만 등록된 것이 정상이다. 캐릭터·전면은 별도 매핑 필요.
- **애니메이션이 안 바뀜:** AnimatedSprite2D는 현재 자동 교체 미지원. 개발자가 교체 경로를 연결해야 한다.
- **Original:** 게임에 포함된 원본으로 돌아간다. 외부 파일이 없어도 게임 실행은 유지된다.

## 현재 확정되지 않은 규격
각 타워의 **정확한 픽셀 치수, 프레임 수·배열, 애니메이션 방향 순서, 파일별 필수 목록**은 이 문서만으로 확정할 수 없다. 게임 원본 이미지·렌더링 구현을 확인하고 타워별 작업 의뢰서에 채워야 한다. 추측한 규격으로 완성 납품하지 않는다.

## 게임 빌드로 채택하기 전 확인

- 세트별 파일명과 `towers/`, `monsters/`, `environment/` 이하 상대 경로를 통일한다.
- 임시 `overrides`가 남아 있으면 폴더를 복사해도 그 파일은 복사본이 아닌 외부 경로를 참조하므로, 정식 세트 PNG가 준비되면 제거한다.
- **현재 게임의 내장 `game/art/` 경로는 아직 세트 폴더와 일치하지 않는다.** 전체 폴더를 게임 빌드 원본으로 사용하려면 게임의 모든 `res://` 참조와 애니메이션 리소스를 함께 이전하고 Godot 임포트/빌드를 검증해야 한다. 폴더 동기화만으로 자동 전환된다고 간주하지 않는다.
