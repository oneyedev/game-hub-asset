# 타워 공격 연출 디자인 규격 v1

타워 패키지는 **건물 후면·공격자/무기·전면 + 발사점 + 비행체/광선 + 명중 연출**을 함께 설계한다. 아처·마법사의 노스킬 관찰(`archer-01`, `mage-01`)이 실제 전투 검수판이고 Art Studio의 **투사체 테스트**가 독립 디자인 검수판이다.

현재 `projectiles-v1`은 실루엣·색·방향·프레임 교체를 검증하기 위한 **절차적 SVG 기준 샘플**이다. 최종 페인팅 원화로 채택했다는 의미는 아니다. 원본 SVG와 [재생성 도구](tools/build_projectile_samples.py)를 함께 제공한다. 새 시안을 제작할 때는 아래 계약을 그대로 유지한다.

## 정규화 계약

| 항목 | v1 계약 |
| --- | --- |
| 파일 경로 | `sets/<세트ID>/projectiles/<종류ID>/flight.png`, `impact.png` |
| 비행 PNG | 256×64 RGBA, 64×64 셀 4열, 좌→우 시간순 |
| 비행 방향·기준점 | 원화는 오른쪽(+X), 각 셀 기준점 `(48,32)`; 게임이 방향 회전 |
| 명중 PNG | 128×32 RGBA, 32×32 셀 4열, 발광 시작→확산→잔광→소멸 |
| 명중 기준점 | 각 셀의 `(16,16)` 중심 |
| 여백 | 셀 밖으로 그림/꼬리가 넘어가지 않게 유지. 임의 trim·셀 재배치·크롭 금지 |
| 광선 예외 | `arcane/flight.png`는 수평 광선 구간. X 양 끝 연결 가능, Y 중심은 32. 게임이 길이만 늘리며 유효 타깃에만 연결 |
| 프레임 시간 | 비행 루프 12fps, 명중 4프레임은 총 0.24초. 공격 주기/피해 횟수와 무관 |
| 발사점 | 타워의 현재 실제 공격자·무기 위치를 따른다. 2인 타워 교대는 기존 발사 기록을 사용 |
| 피격 위치 | 실제 명중 대상의 발 좌표보다 Y -12인 몸체 위치. 렌더링 보정이며 표적 좌표를 변경하지 않음 |
| 광원·가독성 | Village 화풍과 읽히는 작은 실루엣. 불투명 사각 배경·화면 전체 섬광·피해 구역으로 보이는 큰 장판 금지 |

`meta.json`은 규격과 제작 정보를 기록한다. 게임의 프로필 매핑·실제 표시 크기는 `game/projectile_art.gd`가 기준이다. PNG의 색·실루엣·4프레임 그림은 Reload로 교체한다. 기준점·캔버스·기본 표시 크기·프레임 시간의 계약 변경은 코드와 가이드를 함께 갱신하고 새 빌드로 검증한다. 스튜디오의 배율·느린 재생·프레임 선택은 디자인 미리보기에만 적용한다. 미리보기 1배는 월드 표시 크기 기준이므로 실제 노스킬 판의 화면 배율과 가독성도 별도로 확인한다.

## 타워별 역할과 ID

| 타워 | 종류 ID | 읽혀야 하는 역할 |
| --- | --- | --- |
| 아처 I·II | `arrow` | 가는 목재 화살·금속 화살촉·깃. 단계는 실제 피해/주기로 구분 |
| 엘프 I·II | `elf` | 가벼운 잎색 화살·작은 녹색 잔광. 독 스킬로 오인할 독안개 금지 |
| 정령 궁수 | `spirit` | 청록색 정령 화살·가벼운 꼬리. 실제 정령 소환/속성 스킬과 별개 |
| 룬 궁수 | `rune` | 보라색 룬 화살·작은 기하 문양. 기본 피해 유형을 바꾸지 않음 |
| 드워프 I·II | `bullet` | 짧고 따뜻한 금속 총탄·작은 충돌 스파크 |
| 개틀링 | `gatling` | 짧은 황금 예광탄. 회전포의 실제 발사 주기를 따름 |
| 저격수 | `sniper` | 얇고 긴 단발 탄흔. 화면 전체 관통선·추가 관통 피해 금지 |
| 마법사 I·II | `magic` | 푸른 기본 마법탄·짧은 꼬리 |
| 소서리스 | `sorcery` | 밝은 청록색 응집 마력탄 |
| 화염술사 | `fire` | 주황 불꽃 꼬리와 밝은 핵. 노스킬에서는 광역 폭발·잔불 피해 없음 |
| 비전술사 | `arcane` | 연속 보라 광선. 비행탄을 만들지 않고 빔 유효 상태에 연결/해제 |
| 흑마법 | `dark` | 어두운 녹색 마력탄. 빙의 발동 연출과 구분 |
| 저주술사 | `curse` | 진홍 마력탄·작은 저주 문양. 저주진을 자동 생성하지 않음 |
| 부패술사 | `decay` | 황록색 액적·점성 꼬리. 독/산성 안개·감염 스킬을 자동 부여하지 않음 |

## 스튜디오 제작·검수

1. Art Studio를 열고 **투사체 테스트**를 누른다. 실제 웨이브를 시작하지 않아도 사용할 수 있다.
2. 종류·오른쪽/아래/왼쪽/위·1/2/4배·0.25/1/2배속을 바꾸고 비행/명중/프레임 1~4를 검사한다. 수동 프레임은 중간 지점에 멈춰 검사한다. 광선은 길이와 두께·끝점 잔광을 확인한다.
3. **기본 샘플**은 내장 기준본, **원격 시안**은 카탈로그 `projectiles-v1`이다. 초기 원격본은 같은 기준 샘플이다. 실제 시안을 PNG에 반영한 뒤 Reload/F6로 비교한다. 세트의 `files`에는 PNG 28개만 등록하며 SVG·미리보기·메타데이터는 요청하지 않는다.
4. 노스킬 두 판을 시작해 실제 무기에서 출발하고 이동 방향을 따르는지, 명중한 경우에만 피격 연출이 생기는지 확인한다. 미명중·대상 사망·사거리 이탈로 끊긴 광선에 가짜 피격을 남기지 않는다.
5. 피해·투사체 속도·발사 교대·쿨타임·표적 선정·재시작 결과가 디자인 교체 전과 같아야 한다. 애니메이션 4프레임은 4회 공격이 아니다. 광선의 시각 반짝임은 추가 피해가 아니다.
6. PNG 디코딩/알파·캔버스/셀·프레임별 잘림·원격 규격 오류 폴백·PCK의 28 PNG 로딩을 검증한다. 네트워크 없이 내장 샘플로 시작하고, 잘못된 크기의 원격 파일은 해당 내장 PNG로 복구한다.

## 교체·납품

같은 구조로 새 세트를 만들고 `sets.json`의 `root`·`files`를 등록한다. 게임 소스 매핑 키는 `res://game/art/projectiles/v1/<종류ID>/<파일>.png`이며 값은 세트 루트 아래 `projectiles/<종류ID>/<파일>.png`다. 종류를 추가하거나 프로필 매핑을 바꾸면 게임 코드 연결도 필요하다.

기본 샘플 갱신 시 정확한 에셋 커밋의 PNG를 게임 `game/art/projectiles/v1/`에 복사하고 `game/art/projectiles/source.json`의 SHA-256을 갱신한다. 원격 시안은 내장본을 자동 변경하지 않는다. 전투 로직에 연출용 지연·피해·투사체 복제·가짜 폭발 범위를 추가하지 않는다.
